# 系统性能测试与安全性测试报告

## 1. 测试目的

为补充系统测试章节中仅包含功能测试的问题，本次测试从性能测试和安全性测试两个方面对“高校社团经费审批与报销信息管理系统”进行验证。性能测试重点关注高并发审批查询、统计查询和登录认证场景；安全性测试重点关注未授权访问、越权访问、SQL 注入和非法请求方法等常见 Web 安全风险。

## 2. 测试环境

| 项目 | 配置 |
|---|---|
| 前端 | Vue、Element Plus、ECharts、Vite |
| 后端 | Spring Boot、MyBatis、Flowable |
| 数据库 | MySQL |
| 测试地址 | `http://localhost:2026` |
| 测试方式 | 本地接口并发请求、黑盒安全测试 |
| 测试日期 | 2026-06-08 |

本地测试数据库数据规模如下：

| 数据表 | 记录数 |
|---|---:|
| apply | 9 |
| team | 4 |
| approve | 46 |
| reimburse | 2 |
| student | 10 |

说明：本次测试基于毕业设计演示数据量，测试结果主要反映当前系统在小规模数据下的运行情况。若系统后续部署到真实生产环境，仍需基于更大数据量进行压力测试。

## 3. 性能测试

### 3.1 测试指标

本次性能测试主要记录以下指标：

| 指标 | 含义 |
|---|---|
| Success | 成功请求数 |
| Errors | 失败请求数 |
| AvgMs | 平均响应时间 |
| P50Ms | 50% 请求响应时间 |
| P95Ms | 95% 请求响应时间 |
| MaxMs | 最大响应时间 |
| RPS | 每秒处理请求数 |

### 3.2 基础统计接口性能测试

测试条件：并发数 10，总请求数 100。

| 测试接口 | 成功数 | 失败数 | 平均响应时间 | P95 响应时间 | RPS |
|---|---:|---:|---:|---:|---:|
| `/apply/selectAll` | 100 | 0 | 3.55ms | 5.78ms | 2429.19 |
| `/team/selectAll` | 100 | 0 | 2.25ms | 3.45ms | 4232.41 |
| `/approve/selectAll` | 100 | 0 | 12.69ms | 47.23ms | 775.48 |
| `/reimburse/selectAll` | 100 | 0 | 1.73ms | 2.57ms | 5307.55 |
| `/apply/selectAll?team_ID=4` | 100 | 0 | 1.29ms | 1.55ms | 7067.44 |

测试结果表明，在当前数据规模下，系统统计相关接口响应速度较快，所有接口均未出现失败请求。其中审批记录接口 `/approve/selectAll` 相比其他查询接口耗时更高，说明审批记录数量增长后该接口可能成为统计页面的主要性能瓶颈。

### 3.3 高并发审批查询场景测试

测试条件：并发数 30，总请求数 300。该测试模拟多个用户同时访问审批待办池、审批详情和审批记录的场景。

| 测试场景 | 成功数 | 失败数 | 平均响应时间 | P95 响应时间 | 最大响应时间 | RPS |
|---|---:|---:|---:|---:|---:|---:|
| 管理员审批待办查询 | 300 | 0 | 33.51ms | 42.14ms | 52.18ms | 598.66 |
| 报销待办查询 | 300 | 0 | 3.20ms | 5.24ms | 8.17ms | 6359.89 |
| 审批详情 currentTask 查询 | 300 | 0 | 6.58ms | 10.38ms | 16.02ms | 3019.41 |
| 审批记录查询 | 300 | 0 | 9.56ms | 16.77ms | 24.38ms | 2124.80 |

测试结果表明，在高并发审批查询场景下，系统接口均能正常响应，没有出现请求失败。管理员审批待办查询由于涉及 Flowable 工作流任务查询，平均响应时间和 P95 响应时间高于普通数据查询接口，但仍处于可接受范围。

### 3.4 登录接口性能测试

测试条件：并发数 5，总请求数 30。

| 测试接口 | 成功数 | 失败数 | 平均响应时间 | P95 响应时间 | 最大响应时间 | RPS |
|---|---:|---:|---:|---:|---:|---:|
| `/auth/login` | 30 | 0 | 70.47ms | 77.35ms | 78.05ms | 70.38 |

登录接口响应时间明显高于普通查询接口，主要原因是系统使用 BCrypt 进行密码校验。BCrypt 本身具有较高计算成本，可以提升密码安全性，因此该结果符合预期。

### 3.5 前端资源体积检查

构建后较大的前端资源如下：

| 资源 | 大小 |
|---|---:|
| logo 图片 | 约 2032KB |
| ECharts 相关 JS | 约 1086KB |
| Element Plus / 国际化相关 JS | 约 1086KB |
| 全局 CSS | 约 348KB |

前端主要性能风险集中在静态资源体积。毕业设计本地演示影响较小，但若部署到公网，应压缩图片资源，并考虑对 ECharts 等较大依赖进行按需加载。

## 4. 安全性测试

### 4.1 测试用例

| 编号 | 测试项 | 测试方法 | 预期结果 | 实际结果 | 结论 |
|---|---|---|---|---|---|
| S01 | 未登录访问接口 | 不携带 Token 请求 `/apply/selectAll` | 返回 401 | 返回 401 | 通过 |
| S02 | 错误 Token 访问接口 | 携带无效 Token 请求 `/apply/selectAll` | 返回 401 | 返回 401 | 通过 |
| S03 | 角色越权访问 | 社团账号访问 `/admin/selectAll` | 返回 403 | 返回 403 | 通过 |
| S04 | 数据越权访问 | 社团账号访问其他社团申请 `/apply/selectByapply_ID/4` | 返回 403 | 返回 403 | 通过 |
| S05 | 成员越权访问 | 社团账号访问其他社团成员 `/student/selectByID/2021001` | 返回 403 | 返回 403 | 通过 |
| S06 | 合法资源访问 | 社团账号访问本社团成员 `/student/selectByID/2021009` | 返回 200 | 返回 200 | 通过 |
| S07 | SQL 注入测试 | `/apply/selectAll?status=' OR '1'='1` | 不返回异常数据 | 返回 0 条 | 通过 |
| S08 | SQL 注入测试 | `/team/selectAll?team_name=' OR '1'='1` | 不返回异常数据 | 返回 0 条 | 通过 |
| S09 | 登录注入测试 | 密码填写 `' OR '1'='1` | 登录失败 | 业务码 401 | 通过 |
| S10 | 非法方法访问 | 社团账号 POST `/approve/selectAll` | 返回 403 | 返回 403 | 通过 |

### 4.2 安全性测试分析

1. 身份认证方面，系统对未登录请求和错误 Token 请求均能正确拦截，说明 JWT 认证机制生效。
2. 权限控制方面，系统能够区分管理员、指导老师和社团角色。社团用户无法访问管理员接口，也无法访问其他社团的申请和成员数据，说明横向越权控制有效。
3. SQL 注入方面，测试载荷未造成异常查询结果。结合 MyBatis Mapper 中使用 `#{}` 参数绑定的实现方式，可以说明系统对常见 SQL 注入具有一定防护能力。
4. 非法方法访问方面，系统能够拒绝不符合权限规则的请求方法，避免普通社团用户直接调用审批记录管理接口。

### 4.3 发现的安全风险与改进建议

本次测试未发现可直接利用的未授权访问、越权访问或 SQL 注入问题，但仍存在以下可改进点：

| 风险点 | 说明 | 建议 |
|---|---|---|
| CORS 配置较宽松 | 响应中允许 `Access-Control-Allow-Origin: *` | 生产环境建议限制为前端部署域名 |
| 部分接口返回 HTTP 200 但业务码为 401 | 登录失败时接口采用业务码表示失败 | 论文中可说明系统统一使用业务响应码；生产环境可进一步统一 HTTP 状态码 |
| 缺少限流机制 | 登录接口和查询接口未看到限流策略 | 可增加登录失败次数限制、验证码或网关限流 |
| 敏感配置风险 | 数据库密码配置在本地配置文件中 | 生产环境应使用环境变量或配置中心 |
| 审计日志不足 | 当前主要依赖审批记录，安全操作日志较少 | 可增加登录失败、越权访问、关键操作审计日志 |

## 5. 测试结论

通过性能测试可以看出，在当前毕业设计演示数据量下，系统主要查询接口响应速度较快，高并发审批查询场景下也未出现请求失败。登录接口由于采用 BCrypt 密码校验，响应时间高于普通查询接口，但该开销属于安全设计带来的合理成本。

通过安全性测试可以看出，系统已经具备基本的 JWT 身份认证、角色权限控制、资源归属校验和 SQL 注入防护能力。社团用户无法越权访问其他社团的申请和成员信息，未登录用户无法访问受保护接口，常见 SQL 注入载荷未能绕过系统查询条件。

总体来看，系统能够满足毕业设计阶段对性能和安全性的基本要求。后续若进入真实部署环境，建议进一步补充接口限流、生产环境 CORS 白名单、敏感配置保护、审计日志和大数据量压力测试，以提高系统在实际运行环境下的稳定性和安全性。
